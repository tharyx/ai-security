# Lab: Analyzing and Fixing Vulnerabilities in Third-Party Components

**Course exercise:** "Analyzing and Fixing Vulnerabilities in Third-Party Components". Software composition analysis (SCA) in miniature, offline.

**Time:** 30-45 minutes. The packages and advisories are **fictional** (`advisories.json`), so the lab is stable and never accuses a real project.

## Files

| File | Role |
|---|---|
| `requirements.txt` | The vulnerable fixture. Do not edit |
| `my-requirements.txt` | Your working copy. Fix this one |
| `advisories.json` | Fictional advisory database plus a dependency map (for transitive dependencies) |
| `analyzer.py` | The scanner: parse pins, add transitive dependencies, match ranges, propose fixes |

## Steps

1. Scan the fixture:

```text
.venv/Scripts/python caisp-course/ch4-ai-attacks-and-defenses-devops/labs/third-party-vulns/analyzer.py caisp-course/ch4-ai-attacks-and-defenses-devops/labs/third-party-vulns/requirements.txt
```

2. Read each finding: severity, advisory, type, the fixed version, and `via` (a direct dependency, or pulled in by a parent).
3. Edit `my-requirements.txt`. Raise the pins to fixed versions. For a **transitive** finding (`wire-codec`), add your own pin or constraint line, because you do not control the parent's range.
4. Re-scan your file until it is clean. Then run the tests:

```text
.venv/Scripts/python -m pytest caisp-course/ch4-ai-attacks-and-defenses-devops/labs/third-party-vulns -v
```

The last test is skipped until you change `my-requirements.txt`. It then checks three things: no findings, no downgrade, no dependency deleted just to make the scan pass.

5. Cheat: `analyzer.py my-requirements.txt --fix` prints a fixed file.

## Notes for the real world

- Fixing a version is not always a drop-in change. Read the changelog, run your tests and your AI evals again.
- Prefer lock files with hashes (`pip-compile --generate-hashes`, `uv lock`) so the build installs exactly what you scanned.
- Scan model artifacts and container images too, not just Python packages. See the [picklescan lab](../picklescan/README.md) and [06 docker](../../../../06-ai-devsecops/docker/README.md).

## Optional: the real tool

On your own machine, after `pip install pip-audit` (the repo's dev extras include it):

```text
pip-audit -r requirements.txt
```

`pip-audit` queries a live vulnerability database, so it needs the network and results change daily. Try it on a requirements file from one of your own old projects. Alternatives: OSV-Scanner, Trivy, Dependabot, Snyk (commercial). The repo's [runtime-security lab](../../../../06-ai-devsecops/runtime-security/README.md) also has a vulnerability register.
